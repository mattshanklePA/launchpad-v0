## What shipped today

**1. CI/CD loop hardened.**
The CI workflow was firing twice per PR (`push: ["**"]` *and* `pull_request`), and the push run could hang for ~8 minutes and block auto-merge because both reported the same required check name. Fixed `ci.yml` to run on `pull_request` plus `push` to `doc` only, and added a concurrency guard that cancels stale in-progress runs. Merged via branch `ci-single-run`. Every PR now runs one clean CI check.

**2. Cleared the backlog of open PRs.**
- #4 — OMB 2025 AI use case inventory CSV export — merged.
- #6 — cross-bureau duplicate/similarity detection — merged earlier.
- Both landed on `doc`; no open PRs remain.

**3. Office sub-level (Bureau → Office) hierarchy + RLS — issue #7, merged and verified live.**
Added a third org tier below Department → Bureau: **Department → Bureau → Office** for the DoC tenant.
- Migration `db/migrations/doc/0001_office_hierarchy.sql` — additive `office` column on `submissions` and `users`; RLS SELECT/INSERT policies on `submissions` scoped to `role`/`business_unit`/`office` JWT claims. **Ran against the DoC Supabase project.**
- `UnitOption.offices?` in tenant config; offices populated for Census, ITA, NOAA in `doc.ts`. USPTO/DoW unaffected.
- Dependent Office dropdown in the submission wizard; `office-rollup.tsx` + `lib/officeRollup.ts` for drill-down; `visibleSubmissions` office roll-down scoping; `office` threaded through types / APIs / auth / store / seed.
- Unit tests + `docs/ARCHITECTURE.md` updated.

**4. Office-assignment admin UI + tenant-aware bureau dropdown — issue #10, merged.**
- `components/admin/user-management.tsx` bureau dropdown now reads from `getTenant().unit.options` (was hardcoded to USPTO). Dependent Office dropdown appears only when the bureau declares `offices`; bureau change resets office; both persist via existing `PATCH /api/users/:id`.
- `lib/auth.ts` — `BusinessUnit` widened from a USPTO-only literal union to `string` (bureau codes differ per tenant).
- New `loginEmailPlaceholder` in `TenantConfig`; `app/login/page.tsx` uses it, so the DoC login no longer shows `you@dow.mil`.
- `docs/ARCHITECTURE.md` updated.

Verified the office feature end to end as **Karen Ellis** (Census reviewer, session-scoped to office = Decennial):

- **Bureau roll-down** — sees only U.S. Census Bureau; no other bureaus anywhere. ✅

**Key behavior to remember:** the office/bureau claim is captured into the session **at login**. Assigning or changing a reviewer's office requires them to **sign out and back in** before scoping updates.

## Known gaps / follow-ups

1. **Admin UI (#10) not yet live-tested.** It merged, but we stopped before running the UI walkthrough. **This is the first task next session** (checklist below).
2. **GitHub connector is read-only for issues and PRs.** The in-chat connector 403s on create-issue and create-PR (the Claude GitHub *App* has write, but the chat connector mints a narrower token). Net effect: each story needs one manual "Compare & pull request" click, and issues are pasted by hand. Optional future fix; not blocking.
3. **`@claude` sandbox can't run `pnpm`.** It can't self-verify typecheck/lint/test/build — it relies on the PR's CI gate instead (which is sufficient). If we want it to self-verify, add `Bash(pnpm *)` to the workflow's allowed tools.
4. **RLS policies are staged but inert.** The app talks to Supabase via the service_role key (BYPASSRLS), so the office RLS policies don't enforce anything yet. Wiring real per-user Supabase sessions/claims is a future item.
5. **Job Role dropdown** in user management is still USPTO-shaped (intentionally out of scope for #10).
