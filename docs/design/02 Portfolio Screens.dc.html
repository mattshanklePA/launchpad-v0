Note · Signals I wanted and don't have

Nothing on these boards depends on the four below. Each is drawn from the contract as it stands. But each of these would sharpen a screen, and all four look derivable from data you already hold.

01
Gate-block relationships. The worklist ranks by severity, but "this is blocking approvals in two program offices" is stronger. Duplicate-cluster membership already implies it — a blocked-by edge would make it explicit without a dependency model.
02
A deadline per item. The inventory close date drives the reportability queue and is what makes an item urgent rather than merely old. Today only "days open" exists.
03
Confidence on a Plumb proposal. The propose → confirm pattern would batch far better if the system could say which proposals are safe to confirm together and which want reading. The engine already knows when it can't derive a value; the middle ground isn't exposed.
04
Precedent links on a determination. "8 of these follow prior rulings" is the sentence that makes batch confirmation defensible. It needs a pointer from a proposal to the earlier decisions it matches.
